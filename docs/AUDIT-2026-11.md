# Audit, November 2026

Date: 2026-11-12 · Version: 0.6.7 (`dev`) · Previous review: [Production audit, 29 October 2026](PRODUCTION_AUDIT_2026-10-29.md)

## Scope

A documentation, security-boundary and developer-experience audit of the whole
repository, run together with the task-assignment, design-system and
MCP/REST work that landed in this release. It covers the README and docs index,
contributor setup, the task write path (UI, assistant, MCP, REST), design assets
and fonts, supply-chain posture (CI, installer, dependencies) and the unit-test
suite. It is not a penetration test and it does not re-run the production
hosting smoke suite.

## Architecture at a glance

- **Web and API**: Next.js 16 App Router. `proxy.ts` rate-limits and sets CSP
  nonces; pages, Server Actions and route handlers authenticate and authorise
  (`requireWorkspace`, `getWorkspaceForAction`). Business rules live in `lib/`.
- **Data**: PostgreSQL 16 through Prisma, one tenant per workspace, roles
  OWNER, ADMIN, MEMBER and GUEST, private teams for narrower visibility.
- **Background work**: BullMQ on Redis 7. A worker handles email, notifications,
  syncs and monitor checks; beat schedules recurring jobs.
- **Files and secrets**: private S3-compatible storage (Silo or an external
  bucket); application secrets use envelope encryption under a rotatable root key.
- **Machine access**: the in-app assistant, an MCP server at `/api/mcp` and a
  REST API at `/api/v1`, all calling the same task service in `lib/tasks`.
- **Hosting**: VPS with Docker Compose and Caddy, Kubernetes (Helm), Render, AWS,
  DigitalOcean, or a split layout with the frontend on Netlify.
- **Design**: Design-Kit submodule, generated token CSS committed.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the full contract.

## Findings

Severity: High (data exposure or integrity loss), Medium (incorrect behaviour or
meaningful operational risk), Low (hygiene or friction).

| ID | Area | Finding | Severity | Status |
| --- | --- | --- | --- | --- |
| A-01 | Docs | The docs index linked `areas/finance-blog.md`, which does not exist, and left most area guides and top-level guides (MCP, API, Social, Integrations, Monitoring, App reviews) unindexed. | Low | Fixed in this release |
| A-02 | Docs | The root README did not mention the MCP server, REST API or SEO, and described a long list of features without grouping. It is rewritten and every path and command in it was checked. | Low | Fixed in this release |
| A-03 | Tasks | Assignment was a read-modify-write of the assignee set, so two people assigning at once could drop one assignment (lost update). Assignment is now applied so concurrent changes cannot overwrite each other. | High | Fixed in this release |
| A-04 | Tasks | Members could not assign a task to themselves or claim an unassigned one in one step. Added "Assign to me" / "Unassign me" (cards, drawer, `i` shortcut) and an MCP claim tool. | Low | Fixed in this release |
| A-05 | Tasks | The assistant, the MCP tools and the REST API each wrote tasks through their own code path, so validation, permissions and notifications could diverge from the UI. All three now call the shared task service. | High | Fixed in this release |
| A-06 | Tasks | New task positions were derived from `Date.now()`, which can collide or reorder under concurrent creates and moves. Positions no longer depend on the client clock. | Medium | Fixed in this release |
| A-07 | Notifications | Removing an assignee sent them no notification. Assign and unassign now both notify. | Low | Fixed in this release |
| A-08 | Tasks | The data model recorded who is assigned but not who assigned them, so "Assigned by me" and history could not be shown. Assignment rows now store the assigner and history shows who assigned whom. | Medium | Fixed in this release |
| A-09 | Licensing | Paid Gilroy weights (Regular, Medium, SemiBold, Bold) were shipped without a licence. They are removed; the app now uses the Design-Kit fonts (Outfit, Gilroy ExtraBold, Unbounded). | Medium | Fixed in this release |
| A-10 | Tooling | No Node version pin: `package.json` had no `engines` and there was no `.nvmrc`. Added `engines.node >=22.18` and `.nvmrc` (22). `engine-strict` is not set, so the pin is advisory for npm. | Low | Fixed in this release |
| A-11 | Docs | CONTRIBUTING.md used `npm install`, `docker compose up -d` and `npm run db:migrate`, which drifted from DEVELOPMENT.md. Both now use `npm ci`, `--wait`, `db:deploy`, the demo seed and `dev:stack`. | Low | Fixed in this release |
| A-12 | Access | Reported gap: task attachments in a private team's project downloadable by non-members. Not reproduced in the current code: `findDownloadableFile` (`lib/files.ts`) resolves the task's project team and refuses members of a hidden team, and the file library query (`lib/files/service/access.ts`) applies the same filter. No test pins this behaviour. | Medium | Open (verified closed in code; add a regression test) |
| A-13 | Access | Reported gap: dashboard not filtered by private team. Not reproduced: `lib/dashboard.ts` applies `hiddenTeamIds`/`teamScopeFilter` to tasks, shifts, meetings and monitors. Open item is a test that seeds a private team and asserts the dashboard payload. | Medium | Open (verified closed in code; add a regression test) |
| A-14 | Dependencies | `@types/node` is `^20` while the runtime and CI use Node 22. Types can lag APIs available at runtime. | Low | Open |
| A-15 | Supply chain | GitHub Actions are pinned to version tags (`actions/checkout@v4`, `actions/setup-node@v4`, `azure/setup-helm@v4`, `docker/setup-buildx-action@v4`, `actions/download-artifact@v4`) rather than commit SHAs. | Medium | Open |
| A-16 | Supply chain | The documented installer is `curl ... main/install.sh \| bash`, which runs whatever is on `main`. Recommend a release-tag URL with a published checksum, and "download, read, run" as the documented default. | Medium | Open |
| A-17 | Tests | Two unit tests assume GNU `tar` and `stat`: `backup-output-race` and `public-permission-smoke` fail on macOS, which hides real regressions for contributors on that platform. | Low | Open |

## Recommendations and next steps

1. Add regression tests for A-12 and A-13 (private-team attachment download and dashboard payload), then close both.
2. Pin all GitHub Actions to commit SHAs and let Dependabot update them (A-15).
3. Publish release checksums and change the installer documentation to a tag URL plus `sha256sum -c` (A-16).
4. Move `@types/node` to `^22` and run `npm run typecheck` (A-14).
5. Make the two GNU-specific tests portable, for example by detecting `gtar` or avoiding `stat` flags (A-17).
6. Consider `engine-strict=true` in `.npmrc` once all contributors are on Node 22.18 or newer.
7. Done: the 300-line rule is enforced by ESLint `max-lines` and `tests/unit/file-size.test.ts`.
8. Track this table in the next audit and move closed rows into the changelog.
